# Foam machine graph

Foam’s **wikilink graph** is the durable knowledge layer (ADRs, PRDs, features).
VS Code Foam visualizes it in the editor; this folder holds **portable exports**
for agents, CLI, and cdamux.

| File | Purpose |
| ---- | ------- |
| `export.json` | Generated by `cda-graph` → `scripts/foam-graph-export.sh` |
| `../index.md` | Human Map of Content (source of truth for navigation) |

## Regenerate

```bash
bash ~/.cursor/skills/cda-graph/scripts/foam-graph-export.sh --repo /path/to/project
bash ~/.cursor/skills/cda-graph/scripts/foam-graph-export.sh --repo . --merge-orch
```

Validate an intra-issue graph plan before `orch.sh --graph-plan`:

```bash
bash ~/.cursor/skills/cda-graph/scripts/graph-plan-validate.sh plans/graph/issue-42.json
```

Operator guide: [doc/graph-orchestration.md](../../doc/graph-orchestration.md).

`--merge-orch` attaches the live run graph from `.orch/graph/current.json` (workers, integrator, verifier nodes).

## Runtime orchestration graph

During `orch.sh`, the harness writes **only** `.orch/graph/current.json` (gitignored under `.orch/`).
cdamux reads that file for the dynamic Fleet side panel.

Relationship:

```text
foam/graph/export.json   — slow-changing knowledge + optional orch overlay
.orch/graph/current.json — fast-changing run state (workers, phases)
```

See [[../decisions/ADR-005-cda-graph-orchestration|ADR-005]].
